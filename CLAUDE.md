# CLAUDE.md

Project rules for coding assistants (Claude Code reads this file) and for human
contributors.

## What this is

A Gladys Assistant **external integration** for Gecko spas and their in.touch2
Wi-Fi module: a Node.js service (Node 22+, ESM, no build step) running in its
own sandboxed Docker container, talking to Gladys through
[`@gladysassistant/integration-sdk`](https://github.com/GladysAssistant/integration-sdk-js)
(its only runtime dependency) and to the spas over the **local** in.touch2 UDP
protocol (port 10022). It started from the official JavaScript template.

## Commands

```bash
npm install
npm test                                  # node --test, the built-in runner
node --test test/client.test.js           # one file
node --test --test-name-pattern "scene"   # tests whose name matches
npm run lint                              # ESLint
npm run format:check                      # Prettier, as the CI runs it
npm run format                            # Prettier, fix in place
npx github:GladysAssistant/integration-store .   # store admission checks
```

The CI (`.github/workflows/ci.yml`) runs `format:check`, `lint` and `test` on
Node 22 and 24, and builds the Docker image: run the three commands before
pushing.

## Architecture

```
index.js                 SDK client + store + shutdown, nothing else
src/app.js               every SDK handler, registered before connect()
src/spaManager.js        spas: discovery, one client each, states, scene triggers, commands
src/gecko/protocol.js    framing (HELLO, PACKT), requests, parsers — pure, no I/O
src/gecko/client.js      UDP client of one spa: connection sequence, pings, STATP pushes, writes
src/gecko/discovery.js   HELLO via gladys.scanNetwork('udp-active-broadcast') or unicast
src/gecko/packs.js       memory map loading + accessors (read/encode status block values)
src/gecko/packs.json     GENERATED by tools/extract-packs.py — never edit by hand
src/gecko/model.js       capabilities (wired equipment) and snapshot of a spa
src/devices/spa.js       Gladys device + states of a spa
src/scenes.js            scene actions (manifest `scene_actions`)
src/widgets.js           dashboard widget (manifest `widgets`)
src/actions.js           Configuration screen buttons (manifest `actions`)
src/i18n.js              every user-facing text, in en/fr/de/es
src/store.js             /data persistence: client id + known spas
docs/{en,fr,de,es}.md    user documentation, re-hosted by Gladys
test/helpers/fakeSpa.js  in-memory in.touch2 module speaking the protocol
```

## Rules

- **External ids are forever.** A spa is `gladys.externalIds('spa', platformIdOf(spaId))`
  (the spa id of the HELLO answer, lowercased, non-alphanumerics as `-`).
  Feature keys (`water-temperature`, `target-temperature`, `heating`, `p1`…`p5`,
  `bl`, `waterfall`, `li`, `l120`, `cp`, `o3`, `watercare`, `signal`), manifest
  `config_schema`, `actions`, scene and widget keys, scene field values
  (`P1`, `OFF`/`LO`/`HI`, watercare modes) are stored by users: never rename.
- **Every feature carries `name`, `min`, `max`, `read_only` and
  `has_feedback`**: Gladys stores them NOT NULL. `test/manager.test.js` checks.
- **Four languages everywhere.** Every user-facing text — manifest labels,
  descriptions, placeholders, option labels, action messages, widget texts —
  is an object with `en`, `fr`, `de` and `es` (`en` is the fallback).
  `test/manifest.test.js` fails on a missing language. Code texts live in
  `src/i18n.js`. The docs exist in the four languages and are kept in sync.
- **Local only.** The manifest declares `"transports": ["local"]`. Broadcasts
  never leave the container's bridge: discovery goes through
  `gladys.scanNetwork` (port 10022 declared in `network_discovery`), and the
  spa itself is reached in unicast.
- **Never execute geckolib.** `tools/extract-packs.py` reads its pack files
  with the Python AST only. Regenerate `packs.json` with it, never by hand.
- **Tests never touch the network**: use `FakeSpa` (test/helpers) and the
  SDK's `createFakeGladys`.
- **The container rootfs is read-only.** Write only under `/data`
  (`GECKO_DATA_DIR` overrides it in development). Never log tokens.
- **Versions belong to the Release workflow** (Actions → Release). Never edit
  `version` in `package.json` or in the manifest, nor the `docker_image` tag,
  by hand. `test/manifest.test.js` checks they agree.
- **Changelog.** Every user-visible change adds a line under `## [Unreleased]`
  in `CHANGELOG.md` (`### Added`, `Changed`, `Fixed`, `Removed`, `Security`).
  Never write a version heading: the Release workflow moves the section.
- **Manifest.** `scene_triggers`, `scene_actions` and `widgets` need
  `gladys_version >= 5.1.0`. `test/manifest.test.js` ties the manifest to the
  code (handlers, triggers fired, defaults): change both sides together.
- **License.** GPL-3.0-or-later (protocol knowledge and memory maps from
  geckolib). Keep the credits in the README.
- **Style.** Prettier formats, ESLint catches mistakes. Comments explain why,
  in English.
